# Clinic inventory page

Revision 10 adds remembered picture sizes beside the category filters while retaining stable stock controls.

## Fields and daily use

Items contain English and Arabic names, category, unit, current quantity, minimum quantity, and an optional photo. Names follow the app language with a fallback to the available name. SKU, location, supplier, item notes, review notes, import details, and item archival are removed from the interface and current database schema. The item dialog has no stock-action row. There is no expiry tracking.

Current stock has minus/plus buttons which post one unit of usage or receipt. Units and opening stock must be set first. Stock cannot become negative. The workspace Receive stock picker supports larger receipts. The Stock/Movements/Export bar and Import CSV action are removed. Receipts and usage update the item balance directly; there is no movement history or reversal operation. Receive stock requires only a quantity.

Minimum is a plain numeric input in Item details. Changes wait for Save, require item-management permission, and do not change stock or post movements. An unset minimum stays blank until entered. Minimums cannot become negative. Stock units use a bilingual dropdown with common units including Box, Bottle, Pack, Piece, Roll, Tube, and Syringe. Existing spelling is preserved. A nonblank unit stays locked once the item has a known quantity.

Add item defaults to the deepest active category, including either subcategory level, from both the page header and the Items manager. All items leaves the default category choice unchanged. An uncounted item's initial quantity can be entered in Item details with opening-stock permission. Existing balances change through stock controls. Manage inventory contains Categories and Items tabs. Categories support three levels (Category → Subcategory → Second subcategory), English/Arabic names, bulk assignment, and archiving unused categories. Parent filters and counts include descendants. Main category and Subcategory are separate filters; second-level subcategories appear as relative paths in the second dropdown. Changing the main filter resets the subcategory. Category renaming submits only the English/Arabic names and expected revision; it leaves the parent unchanged. New categories choose their parent during creation, and existing subcategories use the separate Move action.

Managers can drag a subcategory's grip to a new parent, retaining its descendants, or drag an item's photo-area grip to another category. The same grips open a Move dialog for touch and keyboard use. Main categories stay at the top level. The server checks expected revisions, active destinations, cycles, duplicate sibling names, and the full subtree's maximum depth. A transaction advisory lock serializes hierarchy changes. Item moves preserve stock quantities. Uncertain drops retry their original request identifier even after realtime refreshes.

Item details and the managed Items list include Delete item with confirmation. Cancel from the list returns to the same Items search; cancel from details retains the unsaved draft. Deletion records a timestamp and removes the item from active queries, counts and photo access. Its retained item record prevents stale writes from recreating it. Deleted items reject metadata, stock, category and photo changes. Direct browser deletion remains denied.

## Item photos

View options sits beside the main-category and subcategory dropdowns. Large retains the existing photo cards. Medium displays photos at half the Large width and height; Small halves those dimensions again and uses full-width rows. On narrow screens, the controls retain their 44 px touch targets. The selection is stored on the device, defaults to Large for missing or invalid preferences, and stays available when local storage is blocked. Size changes only update layout styles, retaining the current filter, item/image/control nodes, selection, and photo cache without an inventory request. Item details keeps its full photo preview.

Every stock card has a full-width image area above its name/category row. Empty areas offer Add image to managers; existing photos have an icon-only Change image button with a label and tooltip. Item details supports upload, replacement, and removal. JPEG, PNG, and WebP source files up to 15 MB are resized to at most 960 px and compressed to WebP (JPEG fallback), at most 300 KiB. Canvas encoding removes source metadata. Visible photos load on demand and use a bounded, session-scoped object-URL cache cleared on reset.

Managers can use Paste image on a card or in Item details, or focus its photo area and press Ctrl+V / Cmd+V. Existing photos use a compact clipboard icon; empty areas show its text label. Clipboard access is requested only from the Paste image button. Unsupported clipboard access or denied permission offers keyboard paste or file selection. Keyboard paste is limited to the target photo area and leaves text fields untouched. Pasted images use the same optimization, private upload, version checks, and retry flow as selected files. Session reset cancels delayed clipboard/file selection results, and photo updates retain focus and unsaved detail fields.

Optimized bytes are stored privately in an Inventory folder in the clinic's connected Google Drive. The separate inventory-images Edge Function validates the current Supabase session and live inventory permissions on every request; patient permissions are not required or granted. Browser metadata exposes a photo version, dimensions, type and size, never Drive identifiers or credentials. Replacements use expected versions; lost replies retry the same upload identifier. Old photos are moved to Drive trash after a successful replacement or removal. Photo writes do not change stock revisions or quantities. Patient sync mappings and snapshots are separate.

## Backend and permissions

Inventory view is required for all operations. Item management controls metadata and minimums. Receiving and usage have separate permissions. Opening stock uses the existing additional permission. Direct table writes remain unavailable to browser roles. RPCs validate current permissions, expected revisions, numeric limits, and stable request identifiers.

The count, wastage, reversal, and item-archive operations are retired. The retire_inventory_movements migration removes the public movement table and history RPC and replaces the private writer so it changes item balances without history inserts. Existing items, quantities, thresholds, categories, photos and revisions remain unchanged. Canonical request payloads retain their IDs and results, including writes committed before migration, to prevent duplicate adjustments after lost replies. No stock history is exposed through the retry cache.

Apply inventory migrations in order, including simplify_inventory_items, retire_inventory_minimum_steps, bilingual_inventory_names, inventory_category_hierarchy, inventory_item_images, inventory_organization, and retire_inventory_movements. Deploy inventory-images with the same configured Google Drive secrets as the existing connection. It authenticates within the handler, so gateway verify_jwt is false. Photo saves lock and recheck the live item in a database trigger so a late upload cannot attach to a deleted item. Item identities, balances, thresholds, units, categories and photos are preserved.

## Layout and verification

Desktop uses a responsive photo-card grid and category navigation. Tablet uses the category selectors. Mobile uses a single card column and bottom sheets. Category and name share a row; current stock, unit/status, and minimum share the next row. Controls have at least 44 by 44 pixel touch targets; current-stock controls retain minus, number, plus order in English and Arabic. Name is the default sort. Category changes retain both native select elements, their unchanged options, the search field, and the page shell. Empty results update the content area without replacing its controls. Identical in-flight reads are shared and stale filter responses are ignored.

Stock clicks update quantities and statuses immediately. Accepted clicks enter a serial queue using the latest confirmed revision, without dimming buttons or waiting for report refreshes. A lost response retains its request ID and pauses unsent clicks until explicit retry; a stale revision cancels unsent clicks for review. Realtime events are coalesced into quiet reconciliation reads that do not lock controls. Navigation warns while stock clicks remain unsaved. Stock changes retain existing rows, icons and photo elements, preserving scroll, focus and selection. Inventory icon rendering targets only new placeholders, avoiding Lucide's repeated replacement of existing SVGs across the application.

Integration checks cover picture-size proportions, row layout, preference storage, unchanged control/image nodes without reloads, all size modes in English/Arabic at phone/tablet/desktop widths, category inheritance at all three levels, managed-list deletion and cancel/return behavior, movement-table/API removal, balance/photo preservation during retirement, permissions, imported blanks, duplicate prevention, safe retries after lost responses, rapid queued clicks, stale revisions, opening stock, minimum limits, schema cleanup, hierarchy paths/filtering, photo compression, clipboard button/keyboard uploads, denied/empty/unsupported clipboard states, delayed clipboard results after session reset, private access, replacement/removal, and mobile/RTL stability. Delayed write/read tests verify immediate quantity updates, unchanged button appearance, persistent dropdown/icon nodes, safe queue recovery, and out-of-order filter replies.
